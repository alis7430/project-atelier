# Feature Design

개발자가 직접 구현할 수 있는 작은 설계와 통합 순서를 제시한다.
한국어로 답하고 현재 프로토타입의 목표와 규모에 맞춘다.
기존 코드 결함 검토가 목적이면 code-review, 현재 구조 평가가 목적이면
architecture-review의 범위를 참고하되 불필요하게 별도 전체 리뷰를 시작하지 않는다.

## 컨텍스트와 실행 범위

- 경로는 프로젝트 루트 기준이다. `AGENTS.md`, `Docs/AI/PROJECT.md`,
  `Docs/AI/CURRENT.md`와 관련 `ARCHITECTURE.md`·`DECISIONS.md`를 확인한다.
  이미 읽은 자료는 재사용하고 이전 결정 이유가 필요할 때만 SESSIONS를 읽는다.
- 생산 코드·자산·설정은 개발자가 변경한다. C# 예시는 채팅에만 제공하고,
  Unity 실행·빌드·테스트·패키지 조작은 수행하지 않는다.
- 설계 요청은 자동 구현이나 문서 자동 갱신 승인이 아니다.
  문서 반영이 명시적으로 요청되면 승인된 문서 범위만 수정할 수 있다.

## 설계 방법

1. 요청한 동작, 현재 단계, 완료 기준을 파악한다. 이미 설명한 목표를 다시 묻지 않는다.
   중요한 의사결정이 막힐 때만 질문하고, 그 외 가정은 밝히고 설계를 진행한다.
2. 관련 기존 클래스·인터페이스·호출자·소유자와 필요한 작성 자산을 읽는다.
   구현된 API, 아직 연결되지 않은 API, 새로 제안하는 API를 구분한다.
3. 기존 책임을 활용한 최소 통합안을 우선한다. 데이터 소유·변경 주체,
   생성·초기화·해제, 이벤트 구독과 상태 전이까지 연결해서 설명한다.
4. 현재 기능을 동작시키는 단계와 나중에 확장할 단계를 분리한다.
   실제 선택이 달라질 때만 대안을 제시하고 이전 비용과 검증 범위를 비교한다.
5. 파일별 수동 적용 순서와 개발자 확인 방법을 제시한다. 기존 파일은 실제 경로를 쓰고
   새 파일·타입·메서드는 '제안, 아직 없음'으로 표시한다. 코드 예시와 함께 필요한
   Inspector 참조·프리팹 조건·초기화 순서를 필요한 만큼 설명한다.

## 현재 프로젝트에 맞춘 판단

- 기술 스택과 현재 진행 상황은 Docs/AI와 실제 소스를 다시 확인한다.
  Slay the Spire 2의 전체 기능을 이번 기능 요구사항으로 자동 편입하지 않는다.
- 맵 화면 단계에서는 MapTestScene이 초기 연결 책임자다.
  생성 → 표시 → 최초 상태 갱신 → 클릭 전달 → 방문 처리의 수동 연결을 우선하고,
  최종 구성 계층이나 전면 리팩터링을 Editor 확인보다 앞세우지 않는다.
- 맵 생성 변경은 BossEnemy 종착점·시작점별 도달 가능성·막다른 길 금지와 대조한다.
  MapConfig의 현재 임시 값으로 게임 규칙을 추정하지 않는다.
- RunManager는 승인된 향후 런 관리 방향이다. 구체 API, RuntimeManager와의 관계,
  등록 방식은 소스와 이번 요청으로 확인하고 정해지지 않은 부분은 제안으로 표시한다.
- 시드·맵 진행의 씬 간 유지와 화면 객체 재사용을 분리한다.
  풀링 설계가 요청되면 단위, 대여·반환 시 상태와 이벤트, 런 종료 시 정리를 함께 다룬다.
  씬 간 유지 요구만으로 디스크 저장을 추가하지 않는다.
- 현재 소스의 네임스페이스·직렬화 필드·공개 API를 존중한다.
  승인된 통일 명칭은 URDev.GameFramework이며, 명칭 이전을 미완료로 가정하지 않는다.
- 개인 Memo.md와 외부 참고 저장소는 참고 자료다. 실제 읽지 않은 외부 구현을
  근거로 들거나 다른 저장소를 사용자가 지정한 저장소로 바꾸어 설명하지 않는다.

## 결과

요청 규모에 맞춰 다음을 연결해서 설명한다. 작은 질문에 모든 항목을 길게 나열하지 않는다.

- 현재 상태와 근거, 달성할 동작 및 제약.
- 권장 설계와 선택 이유, 필요한 경우의 대안.
- 개발자가 적용할 파일·메서드·자산 연결 순서.
- 필요할 때만 제공하는 최소 C# 예시. 기존 API와 제안 API를 구분하고
  설치 패키지·언어 버전과 맞지 않거나 실행하지 않은 부분은 명시한다.
- 개발자가 Editor/테스트에서 확인할 정상·경계·재진입·정리 시나리오.
- 결정되지 않은 질문과 실제 문서 갱신이 필요한 경우의 복사 가능한 수정안.

CURRENT에는 진행 상태, DECISIONS에는 승인된 의도, SESSIONS에는 논의 요약을 제안한다.
AI 권고를 Accepted로 기록하지 않고, 이미 승인된 결정을 같은 주제로 중복 생성하지 않는다.
