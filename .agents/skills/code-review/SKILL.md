# Code Review

현재 요구와 실제 호출 경로에 영향을 주는 문제를 우선 찾아 개발자가 직접
수정할 수 있게 설명한다. 한국어로 답하고 실제 코드 식별자를 유지한다.
리뷰를 구조 전면 재설계나 자동 구현 작업으로 확대하지 않는다.

## 컨텍스트와 실행 범위

- 경로는 프로젝트 루트 기준이다. `AGENTS.md`, `Docs/AI/PROJECT.md`,
  `Docs/AI/CURRENT.md` 및 관련 `ARCHITECTURE.md`·`DECISIONS.md`를 확인한다.
  이미 읽은 컨텍스트는 재사용하고 과거 의도가 필요한 경우에만 SESSIONS를 읽는다.
- 생산 코드·자산·설정 변경, 포맷팅, Unity 실행, 빌드·테스트·프로파일링,
  패키지 조작을 수행하지 않는다. 실행 검증 방법은 개발자에게 제공한다.
- 문서 갱신은 제안하되 명시적으로 반영을 요청받은 문서만 수정한다.
  리뷰 요청이나 C# 예시 요청 자체를 파일 수정 승인으로 해석하지 않는다.

## 검토 방법

1. 요청한 파일·기능·diff의 범위를 확인한다. diff 리뷰라면 변경된 부분을 중심으로
   주변 코드·호출자·인터페이스·사용처를 읽고 기존 문제와 이번 변경의 영향을 구분한다.
2. 관련 분기와 상태 전이를 추적한다. null, 빈 컬렉션, 범위·ID 유효성,
   중복 호출, 재생성, 초기화 전 호출과 정리 후 접근을 필요한 범위에서 확인한다.
3. Unity 수명과 이벤트 등록·해제, 풀 대여·반환 시 상태 초기화,
   참조 소유권을 확인한다. async/코루틴이 있으면 취소와 소유 객체 수명도 본다.
4. 씬·프리팹 연결이 결론에 필요하면 `.meta` GUID와 직렬화 필드를 확인한다.
   오브젝트 이름만으로 컴포넌트 연결을 추정하지 않는다. 필드명·enum 변경은 기존 자산과 대조한다.
5. 할당 위치와 호출 빈도를 함께 설명한다. LINQ나 new의 존재만으로 병목을 확정하거나
   프로파일링 없이 수치·GC 비용을 만들어내지 않는다.
6. 발견 사항을 실제 증거와 발생 조건으로 좁힌다. 테스트·Editor 실행을 하지 않았다면
   정적 추론과 재현 결과를 명확히 구분한다.

## 맵·프레임워크 검토 시 적용

- 맵 규칙은 DECISIONS의 최신 Accepted 항목과 대조한다. 현재 기준은
  BossEnemy 종착점, 모든 시작점의 종착점 도달, 막다른 길 금지다.
- 연결 제거 뒤에도 경로가 유효한지 확인한다. 연결 하나가 있다는 사실과
  종착점에 도달 가능하다는 사실을 동일시하지 않는다.
- MapView 관련 리뷰는 좌표계·anchor·pivot, 노드/선 루트, 입력 차단,
  최초 상태 갱신, 재표시, 구독 해제를 요청 범위에 맞춰 확인한다.
- 알려진 씬 미연결과 임시 MapConfig 값은 개발 단계·통합 준비 항목으로 분류한다.
  실제 테스트를 막을 입력·직렬화 문제는 조건과 영향으로 설명하되 우선순위를 과장하지 않는다.
- 런 상태 보존을 검토할 때 Managers.Clear와 시스템별 Clear의 효과를 읽는다.
  향후 RunManager나 풀링이 이미 연결된 것으로 가정하지 않는다.
- 프레임워크의 승인된 통일 명칭 URDev.GameFramework를 기준으로 실제 소스 명칭을 확인한다. 개인 메모를 요구사항으로 승격하지 않는다.

## 결과

발견 사항을 심각도 순으로 먼저 제시한다. 각 항목에는 다음을 포함한다.

- 심각도와 짧은 제목: P1 주요 동작 차단, P2 조건부 오동작, P3 낮은 영향.
  긴급 차단급 P0는 실제 근거가 있을 때만 사용한다.
- 증거 수준: 정적으로 확인한 결함, 조건부 위험 또는 추가 확인 필요.
- 실제 파일 경로·심볼·확인한 줄, 발생 조건, 사용자/데이터에 미치는 영향.
- 최소 수정 방향과 개발자가 수행할 재현·회귀 확인 방법.

중요한 문제가 없으면 명시한다. 개수 맞추기용 지적이나 취향 차이를 결함으로 넣지 않는다.
요구사항 미구현·향후 개선·스타일 의견은 결함과 분리하고 필요할 때만 덧붙인다.
예시 코드는 필요한 부분만 채팅에 제공하며 실행하지 않은 예시는 검증됐다고 하지 않는다.
마지막에 검토 범위와 미검증 사항을 짧게 밝히고, 문서 갱신 가치가 있으면 제안한다.
